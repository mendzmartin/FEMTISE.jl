Input file reference

The input-file driver solves 1D and 2D problems described by two files:

  • an input file name.dat with the settings, and
  • a potential file name.jl with a Julia function for the potential.
using FEMTISE
run_default_eigen_problem(set_type_potential("path/to/name"))   # without ".dat"
Calling the driver from inside a function

set_type_potential defines the potential by include-ing the potential file. At the top level of a script or the REPL this is transparent. If the driver is called from inside a function (or a do block), that function was compiled before the potential existed and Julia reports "method too new to be called from this world context". Call the driver in the latest world:

function my_workflow(path)
    simulation = set_type_potential(path)
    Base.invokelatest(run_default_eigen_problem, simulation)
end

Format rules

The layout is fixed

The parser reads the file by line number and takes the third whitespace-separated token of each line as the value. Therefore:

  • the file must have exactly the 21 lines shown below, in this order, including the two ## ONLY FOR ... lines;
  • the separator must be = with spaces on both sides;
  • fields that do not apply are left empty, but the line must be present;
  • lists of values (params_potential, analysis_param, output_format_type) are separated by spaces.
full_path_name              = ./results/my_run
dom_type                    = s
nev                         = 10
dimension                   = 2D
sigma                       = -10.0
adhoc_file_name             = ./my_potential
potential_function_name     = my_potential
params_potential_types      = f f f
params_potential            = 1.0 0.0 0.0
analysis_param              = false
output_format_type          = jld2 eigen
## ONLY FOR 1D EIGENPROBLEMS
L                           =
Δx                          =
## ONLY FOR 2D EIGENPROBLEMS
Lx                          = 12.0
Ly                          = 12.0
nx                          = 72
ny                          = 72
different_masses            = false
reduced_density             = false

The potential file

The potential receives the point x (x[1], and x[2] in 2D) and the tuple of parameters, in the order given in the input file:

# my_potential.jl  —  params = (ω, x0, y0)
function my_potential(x, params::Tuple)
    ω, x0, y0 = params
    return 0.5 * ω^2 * ((x[1] - x0)^2 + (x[2] - y0)^2)
end

Guidelines:

  • Use only arithmetic and functions available in FEMTISE (Base, SpecialFunctions); the file is loaded inside the FEMTISE module.
  • Keep the function type-stable and allocation-free: it is evaluated at every quadrature point of every cell.
  • In 2D, the two coordinates may be two particles (e.g. two electrons on a line). Then the potential contains one-body terms $V(x_1)+V(x_2)$ and the interaction $W(x_1-x_2)$.

Parameter sweeps

analysis_param = j λᵢ λ_f Δλ computes the nev eigenvalues for a sweep of the j-th potential parameter. The mesh is built only once. The computed values are

\[\lambda_k = \lambda_i + k\,\Delta\lambda,\qquad k = 1, 2, \dots, \operatorname{round}\!\big(|\lambda_f-\lambda_i|/\Delta\lambda\big).\]

First value of the sweep

In version 0.1.0 the first computed value is $\lambda_i+\Delta\lambda$, not $\lambda_i$. To include $\lambda_i$, start the sweep one step earlier.

Example: analysis_param = 1 0.5 2.0 0.1 sweeps the first parameter over $0.6, 0.7, \dots, 2.0$. Only eigenvalues are stored (ϵ_matrix, of size nev × number of values, and λvector).

Interactive console

run_default_eigen_problem(set_type_potential()) asks for the same information interactively. Option 5 asks for the path of an input file. Options 1–4 run built-in potentials:

OptionPotentialParameters
11D harmonic oscillator $\tfrac12\omega^2(x-x_1)^2$$\omega$, $x_1$
21D symmetric finite Kronig–Penney chaindepth $V_0$ (negative), period, well width, number of wells (odd)
31D finite square welldepth $V_0$ (negative), width
42D isotropic harmonic oscillator$\omega$, $x_1$, $y_1$

Interactive runs also write name_eigen_problem_attributes.dat, a summary of the settings that collect_result_data(false, name) uses to reload the results.
