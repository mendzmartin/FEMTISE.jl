Architecture

FEMTISE.jl is organized in two layers on top of Gridap.jl, which provides meshes, finite element spaces, quadrature and assembly.

 input file (.dat) + potential (.jl)        interactive console
                 \                             /
                  ▼                           ▼
     ┌──────────────────────────────────────────────────┐
     │ DRIVER   run_default_eigen_problem               │   fixed, validated configuration
     │          set_type_potential, input_data          │   (1D/2D, P2 elements, Dirichlet)
     └──────────────────────────────────────────────────┘
                              │
     ┌──────────────────────────────────────────────────┐
     │ LOW-LEVEL INTERFACE (wraps Gridap)               │   full control
     │  make_model ─► measures ─► fe_spaces             │
     │      ─► bilineal_forms ─► eigen_problem ─► solve │
     └──────────────────────────────────────────────────┘
                              │
     ┌──────────────────────────────────────────────────┐
     │ POST-PROCESSING  norms, densities, moments,      │
     │                  entropies, mutual information   │
     │ OUTPUT           write_bin / JLD2 → collect_result_data │
     └──────────────────────────────────────────────────┘

From mathematics to code

Each object of the Theory has one function that builds it:

Mathematical objectFunctionReturns
Mesh $\mathcal T_h$make_model or Gridap.CartesianDiscreteModeldiscrete model
Boundary data (Dirichlet tags/values)make_boundary_conditionsvalues, tags
Domain $\Omega$, boundary $\Gamma$ and quadrature measures $d\Omega$, $d\Gamma$measuresΩ, dΩ, Γ, dΓ
Test and trial spaces $V_h$, $U_h$fe_spacesV, U
Forms $a(u,v)$, $b(u,v)$bilineal_formstwo Julia functions
Matrices $\mathbb A$, $\mathbb B$ and solver settingseigen_problemEigenProblem
Eigenpairs $(\varepsilon_n, u_{n,h})$solveeigenvalues, Vector{CellField}
All of the above in one calleigen_values_and_eigen_vectorseigenvalues, eigenfunctions

The eigenfunctions are Gridap CellFields: they can be evaluated at any point (ϕ[1](Point(0.3))), differentiated (∇(ϕ[1])) and integrated (sum(∫(ϕ[1]' * ϕ[1]) * dΩ)).

Configuration of the driver

The driver fixes the following choices. To change any of them, use the low-level interface.

SettingValue
ElementsLagrange, degree $\ell = 2$, complex-valued spaces (ComplexF64)
Boundary conditionhomogeneous Dirichlet on the whole boundary
1D meshGmsh segment with element size Δx on $(-L/2, L/2)$ or $(0, L)$
2D meshCartesian $n_x\times n_y$ quadrilaterals on a rectangle
Quadrature degree$k_q = 3$
ARPACKtolerance $10^{-8}$, at most 500 restarts (1500 for 1D sweeps), which = :LM, shift sigma from the input
Unitsatomic units, $p = 1/2$ (electron mass)

Design notes

  • Coefficient functions are plain Julia functions. They are compiled and inlined into the assembly loops, so a user-defined potential is as fast as a built-in one.
  • Potentials loaded by the driver are included inside the FEMTISE module. Functions of SpecialFunctions (e.g. erfc) are available there.
  • Parameter sweeps build the mesh once; for each value only the matrices and the factorization are recomputed.
